# star-model

Reproducible dataset, benchmark, and evolutionary fine-tuning pipeline for StarIntel models.

`star-model` builds the corpus. **`llm.starintel.actor` is the training controller**: it receives a dataset manifest, routes synthesis to a configured teacher model, provisions a compatible GPU training backend, launches fine-tuning, records status/checkpoints, and publishes the resulting model artifact.

## Corpus families

- Public StarIntel code repositories, split into task-shaped examples instead of raw repository dumps.
- Public Prolog code and Prolog reasoning/completion tasks.
- Synthetic StarIntel Prolog facts, rules, queries, migrations, and repairs.
- Synthetic StarIntel JSON / JSON-LD documents and transformations.
- Synthetic tool-calling conversations generated by a stronger teacher model.
- Synthetic ingest jobs and failure/recovery cases.
- Synthetic database/data-model migrations.
- Synthetic OSINT tool design tasks.
- Synthetic reusable OSINT skill design tasks.
- Synthetic StarIntel-native tool design tasks.
- Synthetic independent-research tasks that require Brave-grounded evidence and provenance.
- Synthetic document-generation tasks with machine-checkable output requirements.
- Synthetic actor-system generation tasks with runnable-test requirements.

Every record carries source/provenance, generator/model, task family, content hash, and split metadata. Public repository rows also carry repository/license metadata. Generated data must never contain secrets or private repository content.

## Brave-grounded synthetic data

Synthetic research/tool/skill data is generated by `scripts/synthesize_brave.py`. **Brave Search is a required grounding layer for this path**, not an optional fallback.

The pipeline is:

```text
seed topic + task family
          |
          v
Brave LLM Context Search
          |
          +--> public snippets used transiently as teacher context
          |
          v
llm.starintel.actor /v1/chat/completions
          |
          v
family-specific validation + secret rejection
          |
          v
training JSONL
  - messages/tools
  - source URL/title/hostname metadata
  - Brave query
  - grounding-context SHA-256
  - teacher model + prompt version
```

Raw Brave snippets are not copied into the generated training row. The row retains auditable source metadata and a hash of the exact grounding context supplied to the teacher.

The generator fails closed unless the configured Brave plan is acknowledged as permitting the intended storage/training use. Set that acknowledgment only after checking the terms of the plan attached to the API key.

Required environment:

```sh
export BRAVE_SEARCH_API_KEY=...
export STAR_LLM_ACTOR_URL=https://llm.starintel.actor
export STAR_LLM_ACTOR_TOKEN=...
export STAR_SYNTH_MODEL=your/teacher-model
export STAR_BRAVE_TRAINING_RIGHTS_ACK=1
```

Probe Brave without invoking the teacher:

```sh
python scripts/synthesize_brave.py brave-probe \
  "StarIntel document ingest provenance actor API"
```

Generate a bounded batch:

```sh
python scripts/synthesize_brave.py generate \
  --output out/synthetic.jsonl \
  --max-jobs 20 \
  --examples-per-seed 4
```

Generate only one family:

```sh
python scripts/synthesize_brave.py generate \
  --family osint-skill-design \
  --output out/osint-skills.jsonl
```

Configuration lives in `config/synthesis.toml`. Tool-calling rows are rejected unless they contain a non-empty tool schema list, an assistant `tool_calls` message, a tool-role result, and final synthesis. Independent-research rows are rejected unless they cite at least one URL actually returned by Brave.

## Dataset flow

```text
public repos --> harvest --> normalize --> taskify --+
Prolog corpora ------------------------------->     |
                                                      +--> validate --> dedupe --> mix --> manifest
Brave --> llm.starintel.actor --> synthetic data --> |
                                                      +--> fine-tune request --> llm.starintel.actor
                                                                                  |
                                                                                  +--> GPU backend
                                                                                  +--> checkpoints
                                                                                  +--> model artifact
```

The GitHub dataset workflow requires these secrets:

- `BRAVE_SEARCH_API_KEY`
- `STAR_LLM_ACTOR_URL`
- `STAR_LLM_ACTOR_TOKEN`

and these repository variables:

- `STAR_SYNTH_MODEL`
- `STAR_BRAVE_TRAINING_RIGHTS_ACK=1` when the configured Brave plan permits the intended use
- `STAR_BASE_MODEL` when training is enabled

See `config/dataset.toml`, `schema/example.schema.json`, and `.github/workflows/dataset.yml`.

## Evolutionary fine-tuning

The evolution harness treats a fine-tuned adapter as a candidate. A candidate genome contains:

- the training-corpus mixture;
- QLoRA learning rate, rank, alpha, dropout, warmup, and related settings;
- optional lightweight tool-router settings.

A generation is benchmarked on held-out tasks and then selected using a Pareto frontier. The main fitness signal is **accepted useful artifacts**, not eloquence or token count. The default objective weighting is dominated by:

1. independently completed, grounded research artifacts;
2. valid generated documents, including OSINT/StarIntel tool and skill designs;
3. runnable actor systems whose tests pass;
4. correct tool calls;
5. successful ingest jobs.

Research artifacts do not count unless they are marked grounded and independently completed. Actor systems do not count unless their validation/tests pass. A configurable quality floor prevents a candidate from winning by emitting large quantities of junk.

```text
seed genomes
    |
    v
fine-tune requests ---> llm.starintel.actor ---> adapters/checkpoints
    |                                             |
    +---------------------------------------------+
                                                  v
held-out benchmark traces ---> quality gates ---> score
                                                  |
                                                  v
                                         Pareto selection
                                                  |
                                      +-----------+-----------+
                                      |                       |
                                  keep elites             mutate genomes
                                      |                       |
                                      +-----------+-----------+
                                                  |
                                                  v
                                           next generation
```

Create generation zero:

```sh
python scripts/evolve_finetune.py seed \
  --output-dir evolution/g000
```

Build candidate fine-tune requests:

```sh
python scripts/evolve_finetune.py requests \
  --candidate-dir evolution/g000 \
  --manifest dataset/manifest.json \
  --base-model "$STAR_BASE_MODEL" \
  --output-dir evolution/g000/requests
```

Submit them through `llm.starintel.actor`:

```sh
python scripts/evolve_finetune.py submit \
  --request-dir evolution/g000/requests \
  --actor-url "$STAR_LLM_ACTOR_URL" \
  --output-dir evolution/g000/submissions
```

Score held-out JSONL traces and make the next generation:

```sh
python scripts/evolve_finetune.py score \
  --results evolution/g000/benchmark.jsonl \
  --output evolution/g000/scores.json

python scripts/evolve_finetune.py evolve \
  --candidate-dir evolution/g000 \
  --scores evolution/g000/scores.json \
  --output-dir evolution/g001
```

Turn failures into a targeted stronger-teacher repair request:

```sh
python scripts/evolve_finetune.py reflect-request \
  --results evolution/g000/benchmark.jsonl \
  --output evolution/g000/repair-synthesis.json
```

Archive scores through StarIntel's canonical bulk ingest API:

```sh
python scripts/evolve_finetune.py ingest-scores \
  --scores evolution/g000/scores.json \
  --starintel-url "$STARINTEL_URL"
```

The archive is emitted as a canonical StarIntel `document` with `document_kind=fine-tune-benchmark`. Its schema version is configurable in `config/evolution.toml` so the harness can track the deployed server boundary.

## Lightweight neural tool router

`scripts/train_tool_router.py` is an optional tiny PyTorch MLP. It hashes input tokens into a fixed feature vector and predicts a tool label. It provides a cheap routing baseline and can act as a first-stage router before the generative model.

```sh
python scripts/train_tool_router.py train \
  --input data/tool-routing.jsonl \
  --output models/tool-router.pt
```

Rows are simple:

```json
{"input":"research the public DNS history for this domain","tool":"domain_research"}
```

The router's held-out accuracy can feed the same evolution benchmark as a tool-calling signal.

See `config/evolution.toml`, `config/synthesis.toml`, and `schema/benchmark-trace.schema.json` for the main contracts.


## StarIntel archive contract

Install `python -m pip install -r requirements.txt` before emitting archive documents.
Evolution results now use flat StarLang 0.10.1 documents (`id`, `schemaVersion`,
`rawContent`, `contentType`) and validate with the immutable Python consumer.
Benchmark-specific metadata remains under `extensions.star_model`.
The canonical authority is StarLang commit
`765f1673851192bcaf1cdd2f35c47608f979b079`; the Python consumer pin depends on
starintel-doc PR #14 and the StarLang authority PR chain #192 → #194 → #195.
Changing the config version to a historical value is rejected rather than
relabeling documents. Existing benchmark artifacts and training contracts are unchanged.
